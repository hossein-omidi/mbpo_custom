# Focused statistical correction v4.1

This is a **minimal overlay** on `solar_pv_verified_statistics_poa_only_patch_v4.zip` (which in turn expects the v2/v3 workspaces). It does **not** modify pvlib physics, SAC/MBPO training, NSRDB date selection, or the POA optimizer.

## What was mathematically wrong

1. **`MBPO_workspace/src/evaluation.py` published ordinary scenario-bootstrap CIs for the new calendar-stratified evaluation**. That bootstrap treats observed dates as exchangeable random days and ignores the one-random-draw-per-temporal-bin design. With only one observed date per nontrivial bin, a design-based standard error cannot be obtained from a single sample. For evaluations with a selection plan, `summary.json` now uses population-day weights for per-method means and matched-day differences, writes `bootstrap_ci_95pct_kwh: [null, null]`, and labels unweighted sampled-day SD as descriptive. Original no-plan API still works, but its old exploratory iid scenario bootstrap must not be presented as a design-based CI.
2. **Missing measurements were silently dropped from some weighted summary calculations.** Renormalizing on observed bins estimates a different quantity and potentially introduces bias. Now an incomplete metric/subgroup returns unavailable (null) rather than silently changing the finite-population target. Missing weather observations are not omitted when computing each 117-step window average or the diffuse fraction.
3. **Monthly paired-gain plots applied equal weights to observed days** even though sampled bins may have different numbers of eligible dates. Now they first average action-seed replicates *within each scenario*, compute matched-day differences, and calculate the weighted month mean using bin sizes.
4. **Duplicated or unpaired method/day/seed results were not universally rejected.** The central verified summary now enforces a common set of `(scenario_id, evaluation_seed)` observations per method, checks duplicate observations, and refuses nonfinite metric inputs or duplicate sampled dates.
5. **Census interpretation was imprecise.** Exhaustive evaluation of all eligible manifest dates has no *date-sampling* error (conditional on the frozen policies and physical simulator). For a non-exhaustive one-per-bin design, design variance is not identifiable from one realized sample. Neither statement accounts for training randomness, physical model discrepancy or extrapolation to unseen years.

## Mathematical target and variance

For the fixed eligible manifest with `N = sum_h N_h`, and one uniformly selected date in each independent temporal bin:

- `mu_hat = sum_h N_h * y_h / N` (design-unbiased for the finite-manifest mean).
- `d_h = y_A,h - y_B,h` paired on identical dates/initial conditions; `delta_hat = sum_h N_h * d_h / N`.
- `Var(mu_hat) = sum_h (N_h/N)^2 * (1-1/N_h) * S_h^2`, with the finite-population within-bin variance `S_h^2` (unknown when `N_h>1` and only one sampled date is observed).
- An observed-day `sd(ddof=1)` is descriptive sampled-day variation, **not** `sqrt(Var(mu_hat))`, a standard error, or a confidence interval. Boxplot quartiles are likewise sample descriptives, not population confidence limits.
- When multiple **independent date-selection plans** use the same eligible frame and frozen checkpoints, the average of plan-level weighted estimators may be given a *clearly labeled approximate* Student-t interval, with the **plan** as the replicate. This is not an interval for variation across training seeds or future unknown climate years.
- Year-resampling percentiles in the auxiliary stratified JSON are explicitly exploratory sensitivity analysis, **not** design CIs. No figure uses them as validated uncertainty bars.
- The POA oracle remains a *gross-only*, instantaneous, unconstrained reference. It is never used in net-energy differences.

## Validate

```bash
python -m unittest discover -s MBPO_workspace/tests -p 'test_*.py' -v
python -m unittest discover -s SAC_workspace/tests -p 'test_*.py' -v
```

The new regression suite includes unequal date-bin sizes, paired-weight comparisons, exact mathematical enumeration of a small randomization distribution, missing-data rejection, matching/duplicate checks, and exhaustive-census semantics.

For existing results, the offline stratified figure command can rebuild the weighted month plots **without rerunning pvlib**:

```bash
python -m SAC_workspace.workflows.05_stratified_report --help
```

**Important:** `summary.json` is generated by `MBPO_workspace.workflows.03_evaluate`. A previously written `summary.json` still contains the old unweighted and bootstrap values until it is recomputed; never treat the old bootstrap CI as valid for a stratified run.

The root `.gitignore`, plotting layout, model checkpoints, and training logic remain unchanged.
