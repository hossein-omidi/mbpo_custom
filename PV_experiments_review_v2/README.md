## Two high-priority defensive changes to managed evaluations

1. **Checkpoint provenance, cached evaluations and model validation**. For each newly completed evaluation, `PV_experiments/evaluate.py` writes `manager_provenance.json` containing checkpoint file SHA-256, frozen uncertainty-spec checksum, scenario-protocol identity, seed, mode, draw count, model override settings and relevant options. Reusing an existing result requires an exact match. Stale result files are **rejected**, not silently deleted, overwritten or relabeled. The earlier model-validation skip (which checked only the existence of a JSON summary) now also verifies checkpoint, seed, realization, normalized uncertainty assumptions and split identity. Before final held-out testing, a genuine, provenance-matched validation smoke test is required for each selected seed.

2. **Raw nested Monte Carlo checks before across-seed reporting**. `PV_experiments/report.py` checks a full historical-day × realization × controller grid in `all_day_draw_method.csv`. It validates unique records, finite net energy, identical weather fingerprints across the four controllers, exact full held-out scenario ID membership, and agreement of per-method and paired means with `mc_summary.json`. It also requires the *same* weather fingerprints and deterministic baseline energy across seeds before combining results. Mean/SD across independently trained seed means remains separate from MC-within-day variability.

```bash

python PV_experiments_review_v2/install.py --root . --apply
```

It should list exactly four **modified** files:

```
PV_experiments/evaluate.py

```

No `.bak` files, backup folders, Git commands, commits or pushes. The installer is idempotent and rejects unreviewed changes in manager modules by SHA-256.

Run the local tests:

```bash
python -m pytest -q PostProcessing_MC_patch/tests
```
